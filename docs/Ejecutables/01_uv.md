# uv: entorno y dependencias

## Instalar uv (una vez por computador)
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```
Después cierra y vuelve a abrir la terminal.

## Verificar la instalación
```powershell
uv --version
```

## Crear el proyecto como paquete (una vez por proyecto)
```powershell
uv init --package --name ppa-pipeline --python 3.13
```
Crea `pyproject.toml`, `.python-version`, `README.md` y `src/ppa_pipeline/`.

## Crear o actualizar el entorno según `pyproject.toml` + `uv.lock`
```powershell
uv sync
```
También sirve para verificar que `pyproject.toml` está bien escrito: si tiene un error, falla.

## Agregar librerías
```powershell
uv add <libreria>          # dependencia del pipeline (ej: uv add pandas)
uv add --dev <libreria>    # solo para desarrollo (ej: uv add --dev pytest)
```

## Dependencia del pipeline vs. de desarrollo
```powershell
uv add pydantic-settings     # la necesita el pipeline para funcionar → [project] dependencies
uv add --dev pytest          # solo para programar → [dependency-groups] dev
```
⚠️ Nunca uses `pip install` suelto: funciona en tu PC pero **falla en el CI**, porque no queda registrado en `uv.lock`.

## Probar la configuración desde la consola
```powershell
uv run python -c "from ppa_pipeline.config import Settings; print(Settings())"
```
Crea una instancia de `Settings` y la imprime. Los secretos aparecen como `**********`.

## Ejecutar el programa (entry point)
```powershell
uv run ppa-pipeline
```

## Ejecutar una función suelta (para explorar; no reemplaza un test)
```powershell
uv run python -c "from ppa_pipeline.domain.bloques import asignar_bloque; print(asignar_bloque(23))"
```

## Verificar que un paquete se puede importar
```powershell
uv run python -c "import ppa_pipeline.domain, ppa_pipeline.extract; print('OK')"
```

> 💡 `uv run <comando>` ejecuta el comando **dentro del entorno `.venv`** sin tener que activarlo.
